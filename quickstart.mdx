## Prerequisites

- macOS or Linux. basalam uses Salam's POSIX terminal support.
- The Salam compiler, version 0.5.9 or later. Check with `salam version`.

<Steps>
  <Step title="Install Salam">
    Run the official installer, then confirm the compiler is on your `PATH`.

    ```bash
    { curl -fsSL https://raw.githubusercontent.com/SalamLang/Salam/refs/heads/main/install.sh || wget -qO- https://raw.githubusercontent.com/SalamLang/Salam/refs/heads/main/install.sh; } | sh
    salam version
    ```
  </Step>
  <Step title="Add basalam to your project">
    basalam is a package on GitHub, so Salam's package manager installs it. Run `salam init` once if the project has no `salam.toml`, then pin a release tag so your builds stay reproducible:

    ```bash
    salam add github.com/curedbylethe/basalam@v0.4.0
    ```

    `salam add` writes the dependency to `salam.toml` and pins its commit and sha256 in `salam.lock`. Commit both files. The lock is what makes the pin reproducible, and a fresh clone restores the download with `salam deps`.

    <Note>
      To move to another release, run the same command with that release's tag; `salam add` replaces the pin.

      Name the tag rather than running a bare `salam update`. That command moves within the same major version, and until 1.0 the same major covers every `0.y` minor, which this project treats as breaking.
    </Note>
  </Step>
  <Step title="Write a program">
    One `import` line pulls in the whole library. The path names the repository, then the package directory inside it.

    ```salam main.salam
    import "github.com/curedbylethe/basalam/basalam"
    
    struct Hello:
        pub use basalam.BaseWidget
    
        pub func render(buf: basalam.Buffer, bounds: basalam.Rect):
            buf.put_str(2, 1, "Hello from basalam!", basalam.Style { bold = true })
            buf.put_str(2, 3, "Screen size: " + bounds.width + "x" + bounds.height, basalam.StyleDefault)
            buf.put_str(2, 4, "Press q to quit.", basalam.StyleDefault)
        end
    end
    
    func main:
        mut screen := basalam.NewTerminalScreen(Hello {})
        screen.start()
        defer screen.close()
    
        screen.present()
        mut ev := basalam.Event {}
        until screen.next_event(ev):
            if not screen.dispatch(ev) and ev.is_char("q"):
                screen.stop()
            end
            screen.present()
        end
    end
    ```

    The import path ends at `basalam/`, the package directory. Salam loads every `.salam` file in it as one package because its name matches the entry file `basalam.salam`.
  </Step>
  <Step title="Build and run">
    ```bash
    salam build main.salam
    ./main
    ```

    The terminal switches to a full-screen view. Press `q` and your shell comes back exactly as it was.
  </Step>
</Steps>

## What just happened

- `Hello` embeds `BaseWidget`, so it is a widget. It only overrides `render`.
- `NewTerminalScreen` makes `Hello` the root widget, sized to the terminal.
- `start()` switches the terminal to raw mode and the alternate screen and starts the input thread. `defer screen.close()` undoes all of it on every exit path.
- The `until` loop takes one event at a time. `dispatch` offers it to the widgets; `q` is not consumed by any widget, so the loop stops the screen.
- `basalam.Version` is the library version (`0.4.0`); the [demo](/guides/examples) prints it in its title bar.

Read [The event loop](/concepts/event-loop) for the details, or [Writing a widget](/guides/writing-a-widget) to build an interactive one.

## Run the demo

The repository ships a larger demo with panels, ticks, resize handling, and focus movement (Tab and the arrow keys):

```bash
git clone https://github.com/curedbylethe/basalam
cd basalam
make run
```

[Annotated examples](/guides/examples) walks both programs line by line.

## Work on basalam itself

From a clone of the repository:

```bash
make check
```

`make check` runs the formatter check, compiles the library and the examples with `--backend=llvm`, and runs the test suite. `make release-check` checks the release metadata: the version constant, the changelog headings and compare links. CI also runs `make test-llvm`, which builds every test with `--backend=llvm`, and the docs job, which runs `make docs-check` and `make docs-format-check` to validate the pages and fail when `mint format` would rewrite one. With an explicit backend the compiler does not fall back to C, so an LLVM codegen failure fails the build. Run `make help` for the other targets.
