`Keymap` is an opt-in table that maps keys and key sequences to actions. basalam installs none of its own: a screen carries an empty map until you fill it. When an event bubbles to the root without a widget consuming it, the screen offers it to the keymap — but only [`KeyEvent`s](/reference/event). Tick, resize, and mouse events never reach the keymap.

That order means widgets always win. A key a widget consumes never reaches a binding, scoped bindings included. Install the defaults for Tab and the arrows in one line:

```salam
screen.set_keymap(basalam.NewDefaultKeymap())
```

See [`dispatch`](/reference/screen#the-event-loop) for where the fallback sits in the event loop. For task-oriented examples — installing the defaults, binding and scoping keys, sequences, and modes — see [The keymap](/guides/keymap).

## Keymap

A keymap is self-contained: it never holds a screen or a widget. The screen arrives at call time as the `screen` argument to `handle`, which is how an action reaches live screen state.

```salam
pub struct Keymap:
```

Build one with `NewKeymap`, fill it with `bind` and its variants, feed events to `handle`, and release it with `free`.

### Constructors

```salam
pub func NewKeymap(): Keymap
pub func NewDefaultKeymap(): Keymap
pub func NewVimKeymap(on_search: func (Screen*, Event) bool): Keymap
```

| Constructor | Description |
| --- | --- |
| `NewKeymap(): Keymap` | Creates an empty keymap. The root node is created on the first bind, so a zero-valued `Keymap {}` (a `Screen` field default) is usable directly. |
| `NewDefaultKeymap(): Keymap` | Creates a map with the [five default focus bindings](#default-bindings). |
| `NewVimKeymap(on_search): Keymap` | Creates the default focus bindings plus `hjkl` spatial navigation, `gg`/`G` to the ends of the current column, `Esc` back, and `/` handed to `on_search`. See [The vim preset](#the-vim-preset). |

Each call returns an independent map: rebinding one does not touch another.

<Warning>
  Never copy a `Keymap` value. Salam has no move semantics and the fields hold raw `Vector` and `HashMap` pointers, so `mut b := a` makes two owners alias the same buffers and double-free. Create it with `NewKeymap`, install it with [`set_keymap`](#installing-and-extending), and release it with `free`.
</Warning>

### Fields

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `pending_timeout_ms` | `int` | `0` | How long a pending sequence may wait for its next key, in milliseconds. A prefix older than this is dropped lazily, on the next `KeyEvent`; `0` never expires one. |
| `pending_since_ms` | `int` | `0` | When the current pending sequence started waiting, maintained by the map. Public so tests can force a timeout without sleeping; applications set `pending_timeout_ms` instead. |

See [Sequences](#sequences) for the full timeout behavior.

## Binding

An action is a `func (screen: basalam.Screen*, event: basalam.Event): bool`. Only lambda literals can be stored in a function value, so every action — yours and the library's defaults — is a lambda. The screen is a pointer so an action can move focus and mark the screen dirty:

```salam
(screen: basalam.Screen*, event: basalam.Event): ret screen[0].focus_next() end
```

| Method | Description |
| --- | --- |
| `bind(key: term.Key, action: func (Screen*, Event) bool)` | Binds one key in the global scope. A later `bind` of the same key replaces this one (last write wins). |
| `bind_for(widget_id: int, key: term.Key, action: func (Screen*, Event) bool)` | Binds one key for the widget with this ID: the action runs when that widget, or one of its descendants, has the focus. `NoWidget` binds globally. |
| `bind_seq(seq: str, action: func (Screen*, Event) bool)` | Binds a key sequence in the global scope. |
| `bind_for_seq(widget_id: int, seq: str, action: func (Screen*, Event) bool)` | Binds a key sequence for the widget with this ID. `NoWidget` binds globally. |
| `unbind(key: term.Key)` | Removes the global binding for one key. A no-op when there is none. Scoped bindings are not touched; use `bind_for` to replace one, or `unbind_for` to drop one. |
| `unbind_for(widget_id: int, key: term.Key)` | Removes one widget's binding for one key: `bind_for`'s inverse. Only that widget's override goes, so the global row and every other widget's override on the same key still apply, and no node is deleted. A no-op when the map is empty, the key was never bound, or that widget never bound it. `unbind_for(NoWidget, key)` equals `unbind(key)`, and a pending sequence is reset. |
| `handle(screen: Screen*, event: Event): bool` | Offers one event to the map. Only `KeyEvent`s are handled; any other kind returns `false` and leaves a pending sequence untouched. Returns whether the matched action reported the key consumed. |
| `free()` | Releases every node's children map and binding vector, then the node storage. Call once. |

`bind_seq` and `bind_for_seq` decode `seq` one rune at a time, so `"gg"` is two keys. An empty string is ignored and binds nothing.

A key's identity includes its code, the `Ctrl`/`Alt`/`Shift` modifiers, and — for a character key — the character. `Space` (code `KeySpace`) and `Ctrl+Space` (a character key whose `ch` is `" "`) are therefore two different bindings.

## Default bindings

`NewDefaultKeymap` builds exactly five rows. Nothing installs it for you: `NewScreen` and `start()` touch no bindings.

| Key | Action |
| --- | --- |
| `Tab` | `focus_next()` |
| `Up` | `focus_up()` |
| `Down` | `focus_down()` |
| `Left` | `focus_left()` |
| `Right` | `focus_right()` |

In the default map, `q` and every other key stay unbound, so they bubble to your loop for the quit pattern.

<Note>
  Shift+Tab is deliberately not bound. Salam decodes the backtab sequence (`ESC [ Z`) to `KeyUnknown`, so binding it would need an escape literal. If your terminal sends a Shift+Tab sequence you can decode, bind it yourself with `term.Decode`. The vim preset omits it for the same reason: a decoded backtab stays `KeyUnknown` with its raw sequence, so you bind that sequence with `bind` like any other key.
</Note>

## The vim preset

`NewVimKeymap(on_search)` is a convenience map, not a mode system: modes stay in your application. It starts from `NewDefaultKeymap` and adds vim-style rows, so Tab and the four arrows keep working. Install it with `set_keymap`:

```salam
screen.set_keymap(basalam.NewVimKeymap(on_search))
```

| Key | Action | Source |
| --- | --- | --- |
| `Tab` | `focus_next()` | default map |
| `Up` | `focus_up()` | default map |
| `Down` | `focus_down()` | default map |
| `Left` | `focus_left()` | default map |
| `Right` | `focus_right()` | default map |
| `h` | `focus_left()` | preset |
| `j` | `focus_down()` | preset |
| `k` | `focus_up()` | preset |
| `l` | `focus_right()` | preset |
| `gg` | Repeated `focus_up()` to the top of the current column | preset |
| `G` | Repeated `focus_down()` to the bottom of the current column | preset |
| `Esc` | `pop_focus()`, only while a pushed focus remains | preset |
| `/` | `on_search(screen, event)`, the application's action | preset |

`gg` and `G` move spatially until the direction is exhausted, so they keep the focused widget's column rather than jumping by ordinal position.

**Enter and Space are the widget's job.** The preset binds neither. [`dispatch`](/reference/screen#the-event-loop) offers every key to the focused widget first, where [`Button`](/reference/button), `Checkbox`, `List` and `Modal` already act on them, so a binding would only fire for a widget that declined the key. There is no generic "activate the focused widget" to bind; see [Key bindings](/concepts/event-loop#key-bindings).

**`Esc` is guarded.** It pops one focus level only when the focus stack is deeper than one. At the root the key is left unconsumed, so your loop can still use it to quit or cancel. An open `Modal` keeps its own Esc handling and consumes the key before the keymap sees it.

**`/` is yours.** The preset runs `on_search` and returns its boolean as the dispatch result, so pass an action returning `false` if you want `/` inert. A focused [`Input`](/reference/input) consumes printable keys before the keymap, so `/` reaches the preset only when the widget declines it.

The map is plain data: install it with `set_keymap`, never copy it, and see [Installing and extending](#installing-and-extending) for replacement and extension.

## Resolution

When a `KeyEvent` reaches the keymap, basalam resolves it in this order:

1. The key walks a single trie keyed by a canonical key string. A single key is one hash probe at the root; a sequence walks one node per event.
2. At the matched node, the focused widget and its ancestors are checked nearest-first: the closest scope with a binding for that node wins.
3. If no scoped binding applies, the global (`NoWidget`) binding runs.
4. If neither applies, `handle` returns `false` and the key bubbles on.

The scope walk is O(tree depth) and only runs at nodes that carry scoped bindings; a global-only map is strictly one probe per key.

## Sequences

- A node that has both a binding and children defers: its single-key binding fires only when the next key breaks the path. While a longer sequence keeps matching, the longer one wins.
- A key that does not continue a pending prefix resets it and is reprocessed from the root, so a sequence followed by an unrelated bound key still triggers that key.
- A pending prefix can time out. The check is lazy — it runs only when the next `KeyEvent` arrives, never on a timer — and `pending_timeout_ms` defaults to `0`, which never expires a prefix. Set it on the map:
  ```salam
  screen.keymap.pending_timeout_ms = 700 // abandon a prefix after 700ms
  ```
  Nothing fires from the timeout alone: an expired prefix is dropped silently and the arriving key is processed as a fresh start, so it may open a new sequence or trigger a single binding.
- Non-key events (tick, resize, mouse) never reach the keymap and never evaluate the timeout, so a pending sequence survives them. Elapsed time still counts, though: if only non-key events arrived during the gap, the next `KeyEvent` evaluates the full elapsed time.
- An invoked action resolves the key: nothing is reprocessed after an action runs, even when the action returns `false`.
- An unbound `Esc` or `Ctrl+C` leaves the pending state reset and returns `false`, so the loop's auto-stop still works. A consumed `Esc`, such as one an open Modal takes, never reaches the keymap fallback.

## Installing and extending

A screen exposes its map as the [`keymap` field](/reference/screen#fields). Install a whole map with `set_keymap`, or extend the current one in place through the field.

```salam
screen.set_keymap(basalam.NewDefaultKeymap()) // replace with the defaults
screen.keymap.bind(term.Decode("q"), my_quit) // extend the installed map in place
```

`set_keymap(km)` frees the current map's buffers and then installs `km`. It is the only safe way to swap a map, and it leaves the new map with no pending sequence. Ownership of `km` transfers to the screen, so do not free or use it afterward.

- **Replace**: pass a freshly built map. Pass `NewKeymap()` to clear every binding.
- **Extend**: bind through `screen.keymap`. This adds to the installed map with no copy, and rebinding a default key replaces it (last write wins).

[`close()`](/reference/screen#terminal-lifecycle) frees the screen's keymap. A map you build and never install is yours to `free`.

<Warning>
  Never assign to `screen.keymap` directly. The field holds raw buffers, so assigning would leak the current map's storage and then double-free on `close()`. Use `set_keymap` to replace the map, or `screen.keymap.bind` to extend it.
</Warning>

## Example

Install the defaults before the loop. The keymap consumes Tab and the arrows before the loop sees them, so the loop only has to handle `q`:

```salam
include "basalam/basalam.salam"

func main:
    mut screen := basalam.NewTerminalScreen(MyRoot {})
    screen.start()
    defer screen.close()

    screen.set_keymap(basalam.NewDefaultKeymap()) // Tab + arrows move the focus

    screen.present()
    mut ev := basalam.Event {}
    until screen.next_event(ev):
        if not screen.dispatch(ev) and ev.is_char("q"):
            screen.stop()
        end
        screen.present()
    end
end
```

## Modes

basalam ships no modes and two stock maps: `NewDefaultKeymap` and `NewVimKeymap` are plain data your app installs, swaps or replaces, so modes stay application territory. Your app can wrap the library in its own state and an action can call `set_keymap` to swap the whole map — for example a normal map that binds `i` to an insert map, and an insert map that binds `Esc` back. The swapped-in map starts with no pending sequence. A consumed Esc, such as an open Modal's, never reaches the keymap fallback, so a mode's Esc binding fires only while no widget takes the key. See [Focus](/concepts/focus) for the navigation methods your actions call.
