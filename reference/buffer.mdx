A `Buffer` is a grid of `Cell`s. Widgets draw into it; they never write to the terminal. Every write outside the grid or outside the buffer's clip rect is silently dropped, so drawing can never fail.

<Warning>
  A `Buffer` holds two grids: a back grid widgets draw into and a front grid of what the terminal currently shows. `flush()` writes the touched cells that differ from the front grid and skips clean rows. Mark cells with `set`, `fill`, `put_str`, or `clear`. A direct write to `cells` is not marked, so `diff` can skip it. What is still absent: wide-character support (each cell holds one codepoint and is assumed to be one column wide, epic 2) and cursor placement for text input.
</Warning>

## Cell

```salam
pub struct Cell:
    pub ch: str = " "
    pub style: Style = StyleDefault
end
```

<ResponseField name="ch" type="str">
  Exactly one codepoint. A blank cell holds `" "`.
</ResponseField>

<ResponseField name="style" type="Style" default="StyleDefault">
  The resolved [`Style`](/reference/style) this cell is drawn with. `StyleDefault` asks for the terminal's default style. The buffer turns the value into bytes when it emits the frame, so a cell never holds escape sequences.
</ResponseField>

## Buffer

```salam
pub struct Buffer:
    pub width: int = 0
    pub height: int = 0
    pub cells: Vector<Cell> = Vector {}
    pub front: Vector<Cell> = Vector {}
    pub clip: Rect = Rect {}
    pub focused: bool = false
    pub tier: ColorTier = ColorTier.TrueColor
    pub force_full: bool = true
end
```

<ResponseField name="width" type="int">
  Number of columns.
</ResponseField>

<ResponseField name="height" type="int">
  Number of rows.
</ResponseField>

<ResponseField name="cells" type="Vector<Cell>">
  The back grid: row-major storage where widgets draw. The cell at `(x, y)` is `cells[y * width + x]`. Write it through `set`, `fill`, `put_str`, or `clear`, which mark the cell. A direct assignment is not marked, and `diff` can skip it. `get` bounds-checks.
</ResponseField>

<ResponseField name="front" type="Vector<Cell>">
  The front grid: what the terminal currently shows, with the same length and layout as `cells`. Widgets never write it; only `commit()` advances it.
</ResponseField>

<ResponseField name="clip" type="Rect">
  Writes outside this rect are dropped. `NewBuffer` sets it to the whole grid. While a widget renders, the screen narrows it to that widget's bounds.
</ResponseField>

<ResponseField name="focused" type="bool">
  `true` while the screen renders the focused widget. Use it to draw a focus indicator.
</ResponseField>

<ResponseField name="tier" type="ColorTier" default="ColorTier.TrueColor">
  The colour capability of the terminal this buffer is drawn for. The buffer lowers every cell's `Style` to this tier when it emits a frame, so an `Rgb` foreground becomes the nearest ANSI colour on a 16-colour terminal and no colour at all at `Off`. `Screen.start()` sets it to [`DetectTier`](/reference/color#capability-detection) once, when it takes the terminal; a buffer built by hand with `NewBuffer` keeps the default, so a headless render is always true colour. `resize` preserves it.
</ResponseField>

<ResponseField name="force_full" type="bool" default="true">
  `true` when the next `diff()` must serialize the whole frame instead of only the changed cells. `NewBuffer` and `resize` set it; `commit()` clears it once the front grid has caught up.
</ResponseField>

### Copies share cells

A `Buffer` reaches `render` by value, but both grids live in `Vector`s, and copies of a `Vector` share storage. The back grid (`cells`) and the front grid (`front`) are shared this way. A widget writing through its copy writes the screen's one back grid, and `commit()` through any copy advances the shared front grid. The scalar fields `clip`, `focused`, `tier`, and `force_full` belong to each copy, which is how the screen gives each widget its own clip without affecting the others.

Widgets write only through the back grid; nothing but `commit()` ever touches `front`. Only the owner of the original buffer may `resize`, `flush`, or `free` it, because those replace or release the storage the copies share.

## Functions and methods

```salam
pub func NewBuffer(width: int, height: int): Buffer
```

Creates a blank grid with `clip` covering all of it. A negative size is treated as zero.

| Method | Description |
| --- | --- |
| `area(): Rect` | The rect covering the whole grid, `(0, 0, width, height)`. |
| `set(x: int, y: int, cell: Cell)` | Writes one cell. Ignored outside the grid or the clip. |
| `get(x: int, y: int): Cell` | Reads one cell. Returns a blank `Cell` outside the grid. Ignores the clip. |
| `put_str(x: int, y: int, text: str, style: Style)` | Writes text left to right, one codepoint per cell, all in `style`. Cut off at the clip; never wraps. |
| `fill(r: Rect, ch: str, style: Style)` | Sets every cell of `r`, clipped, to `ch` in `style`. |
| `clear()` | Resets every cell to blank, ignoring the clip. |
| `row_text(y: int): str` | The characters of row `y` of the back grid, without styles. `""` outside the grid. Meant for tests and debugging. |
| `resize(width: int, height: int)` | Replaces both grids with blank ones and resets the clip, forcing a full repaint on the next `diff()`. Keeps `tier`: a resize is not a new terminal. Only the original buffer may call it. |
| `ansi(): str` | The whole grid as one frame: per row a cursor move and every cell, switching style only where it changes. Nothing is diffed. For tests and debugging. |
| `diff(): str` | The bytes `flush()` would write: the whole frame (see `ansi`) while `force_full`, otherwise the touched cells that differ from `front`, skipping clean rows. `""` when nothing marked differs. |
| `commit()` | Copies marked cells on marked rows into the front grid (every cell while `force_full`), then clears the marks and `force_full`. |
| `flush()` | Writes the changed cells (see `diff`) to the terminal, then commits. Writes nothing when the diff is empty. |
| `free()` | Releases both grids. Call once, on the original. |

## Style transitions

A frame starts from the terminal's default style: its first cell is drawn on the assumption that nothing is set. From there, `ansi()` and `diff()` compare each cell's style with the style the terminal is in and, where they differ, emit `StyleSgrOff(previous, tier)` followed by `StyleSgr(next, tier)`. The frame ends by emitting `StyleSgrOff(last, tier)` for the last style it wrote; that is `""` when the last style is `StyleDefault`, so the close needs no condition. `diff()` carries the current style across runs, so a row that continues in the same style emits no sequence at all.

Neither function emits a terminal reset. A reset would discard state instead of describing it, so the frame contract is made of SGR attribute and colour codes only. `Screen.start()` and `Screen.close()` reset the terminal, because they set it up and tear it down rather than draw a frame.

## Testing what a widget draws

Because a buffer is plain memory, you can render a widget and inspect the result without a terminal:

```salam
mut buf := basalam.NewBuffer(12, 1)
defer buf.free()
w.render(buf, w.bounds())
println "[" + buf.row_text(0) + "]" // [apples: 2   ]
```
