A `Screen` owns the terminal session. It holds the widget [tree](/reference/tree), the [buffer](/reference/buffer), and the channel the input thread sends [events](/reference/event) on. You create one per program.

```salam
mut screen := basalam.NewTerminalScreen(MyRoot {})
screen.start()
defer screen.close()
```

<Warning>
  Call `defer screen.close()` on the line right after `start()`. `start()` puts the terminal in raw mode and switches to the alternate screen. `close()` undoes both, and `defer` makes sure it runs on every return path.
</Warning>

## Constructors

```salam
pub func NewScreen(root: dyn Widget, width: int, height: int): Screen
pub func NewTerminalScreen(root: dyn Widget): Screen
```

`NewScreen` creates a screen of `width` x `height` cells. `root` becomes widget `0` and is sized to the whole screen. Nothing touches the terminal until `start()`, so a screen made with `NewScreen` works headlessly in tests.

`NewTerminalScreen` does the same with the current terminal size.

<ResponseField name="focused" type="dyn Widget">The widget that receives events first.</ResponseField>

<ResponseField name="running" type="bool">`true` from `start()` (or the start of `run`) until `stop()`.</ResponseField>
<ResponseField name="tree" type="Tree">The widget registry. Prefer `add` and `widget`.</ResponseField>

<ResponseField name="mouse" type="bool" default="false">When `true`, `start()` enables mouse reporting and clicks arrive as `MouseEvent`s. Set it before `start()`.</ResponseField>
<ResponseField name="keymap" type="Keymap" default="Keymap {}">The opt-in [keymap](/reference/keymap) consulted as a fallback for a `KeyEvent` no widget consumed. Never assign a `Keymap` directly.</ResponseField>
<ResponseField name="dirty" type="bool">`true` requests a full repaint. Set by a resize, a tick from `run_with_tick`, an added widget, `raise` / `unraise`, a keymap-consumed key, and `invalidate` of an unknown id or an empty rect. Set it yourself after changing state outside `dispatch`; a tick you dispatch yourself does not set it. A consumed widget event does not set it. That event queues the widget's own bounds.</ResponseField>
<ResponseField name="focus_stack" type="Vector<int>">Widget IDs; the last entry is the focused widget. Change it only through the focus methods, which keep `focused` in sync and queue the old and new bounds.</ResponseField>

## Building the tree

| Method | Description |
| --- | --- |
| `add(parent: int, w: dyn Widget): int` | Adds `w` under `parent` (`RootId` for top level) and returns its ID. Unraised widgets paint in the order you add them. The first focusable widget added while nothing has focus receives it. |
| `widget(id: int): dyn Widget` | The widget with this ID; the root for an invalid ID. |
| `focused_id(): int` | The ID of the focused widget, or `NoWidget` when nothing has focus (events then start at the root). |
| `hit_test(x: int, y: int): int` | The ID of the widget drawn at cell (`x`, `y`), or `NoWidget`. See [Hit testing](#hit-testing). |
| `fit_root()` | Gives the root the whole buffer. |
| `resize(width: int, height: int)` | Reallocates both buffer grids and refits the root, forcing a full repaint on the next frame. |

## Focus

See [Focus](/concepts/focus) for the rules behind these methods.

| Method | Description |
| --- | --- |
| `focus(id: int): bool` | Focuses `id`, replacing the top of the focus stack. `false` if `id` is not focusable. |
| `push_focus(id: int): bool` | Focuses `id` and remembers the previous focus underneath it. |
| `pop_focus(): bool` | Returns to the focus before the last `push_focus`. `false` if the stack is empty. |
| `can_focus(id: int): bool` | Whether `id` names a focusable widget. |
| `focus_next(): bool` / `focus_prev(): bool` | Next or previous widget in the [focus order](#raise), wrapping inside it. Not always ID order. |
| `focus_up(): bool` / `focus_down(): bool` / `focus_left(): bool` / `focus_right(): bool` | Nearest widget in that direction, chosen from the focus order. |

Each returns `true` when the focus moved. Every change queues the old bounds and the new bounds, so the next `present()` redraws those two indicators.

`push_focus` and `pop_focus` are unchanged by raise. They push and pop any focusable id. They do not raise the widget, and they do not walk the focus order.

## Raise

```salam
pub func raise(ids: Vector<int>)
pub func unraise(ids: Vector<int>)
pub func raise_subtree(id: int)
pub func unraise_subtree(id: int)
```

`raise` assigns every id in the call one fresh stamp, shared by the whole call, so those widgets are one layer above everything raised earlier and above every unraised widget. Within the layer, paint order stays ID order. Paint order overall is ascending `(stamp, id)`: a lower stamp paints first, and the same stamp paints in ID order. An id that is not in the tree is recorded and does not crash. It affects painting only once that id is registered.

The focus order is the focusable widgets in the topmost stamp layer, ascending id. When nothing is raised, or that layer has no focusable widget, the order is every focusable widget, ascending id. `focus_next` and `focus_prev` wrap inside that order. A focus outside the order jumps to the first entry on `focus_next` and the last on `focus_prev`. The spatial methods search the same order.

When that order is non-empty and the current focus is outside it, `raise` saves one restore id (the current focus) and moves to the first id of the new order. There is only one saved id. A later `raise` that also moves the focus replaces it. Otherwise `raise` leaves the focus and the saved id unchanged. The move uses `focus`, so it replaces the top of the stack. It does not `push_focus`.

`unraise` writes stamp `0` on every id, so those widgets return to plain ID order. It is idempotent: an id that was not raised, or that is not in the tree, stays at `0`. It does not rewind the stamp counter, so a later `raise` is still a new layer. When nothing remains raised, it focuses the saved id if that widget is still focusable, otherwise the first focusable widget, and then clears the saved id. If the saved id is not focusable and nothing else is, it clears the focus. While a layer remains, it leaves the focus alone when the current focus is still in the new order. Otherwise it focuses the first id of that order, or clears the focus when the order is empty.

`raise_subtree(id: int)` and `unraise_subtree(id: int)` do the same for a widget and every descendant of it. `raise_subtree` gives the whole subtree one fresh stamp, so it is one layer above everything else, and inside the layer each parent still paints before its children. `unraise_subtree` returns the subtree to plain ID order. Both follow the focus rules of `raise` and `unraise`: `raise_subtree` moves the focus into the layer and saves the old one, and `unraise_subtree` restores it. An id that is not in the tree, including `NoWidget`, does nothing. A [Modal](/reference/modal) opens with `push_focus` and then `raise_subtree`, and closes with `unraise_subtree` and then `pop_focus`.

## Terminal lifecycle

| Method | Description |
| --- | --- |
| `start()` | Raw mode, alternate screen, hidden cursor, mouse reporting if `mouse` is set, a buffer sized to the terminal, the input thread, and, on POSIX, the resize watcher. |
| `stop()` | Ends the loop. `next_event` returns `false` once the queue is drained. Safe to call more than once. |
| `close()` | Stops the loop, restores the terminal exactly as `start()` found it, joins the input thread and the resize watcher, and frees the screen's storage, including its keymap. Safe to call more than once. |

## The event loop

| Method | Description |
| --- | --- |
| `next_event(event &: Event): bool` | Waits for the next event. Returns `false` once the screen is stopped and every queued event was delivered. |
| `dispatch(event: Event): bool` | Handles one event synchronously. A `ResizeEvent` first resizes the screen. Then the event goes to a starting widget and bubbles up: the widget under the cursor for a mouse event, the focused widget for everything else. An unconsumed `KeyEvent` is then offered to the [keymap](/reference/keymap) fallback. Returns `true` if a widget or the keymap consumed it. See [Hit testing](#hit-testing). |
| `draw()` | Repaints pending regions, or every widget when `dirty` is set, more than four regions are pending, or those regions cover more than half the screen. Does nothing when nothing is pending. Paint order stays ascending `(stamp, id)`. |
| `present()` | Returns immediately when nothing is pending. Otherwise `draw()`, then, once attached, writes only the cells that changed since the last frame. Clears `dirty` and the pending regions. A change you make outside `dispatch` needs `dirty = true` or `invalidate(id)`. |
| `invalidate(id: int)` | Queues a repaint of widget `id`'s bounds. An unknown id, or a widget whose rect is empty, marks the whole screen. Legal before `start()`. A region is that widget's bounds, not its subtree. |
| `post(event: Event): bool` | Queues an event as if the input thread had produced it. Safe from any thread. |
| `run()` | Runs the loop until `stop()`. Redraws only when something changed. An unconsumed Ctrl+C stops it. |
| `run_with_tick(on_tick: func ())` | Like `run`, and also calls `on_tick` on the main thread for every `TickEvent`. |

### Hit testing

```salam
pub func hit_test(x: int, y: int): int
```

`hit_test` returns the ID of the widget drawn at the 0-based cell (`x`, `y`), or `NoWidget` when no widget covers it. The scan is reverse paint order: higher stamp first, and within a stamp the higher ID first. The first widget whose rect contains the cell and whose [`hits`](/reference/widget#hits) returns `true` wins. A widget may paint and still refuse hits; the scan then continues to the widget under it. With nothing raised, paint order is ID order, so a child beats its parent and a later sibling beats an earlier one. A raised widget beats every widget in an earlier layer, whatever its ID. Widgets with empty bounds never match. The root covers the whole buffer and accepts hits by default, so inside the screen the answer is never `NoWidget` unless you shrank the root or every widget on that cell refuses hits.

`dispatch` uses it for mouse routing:

| Event | First widget offered the event |
| --- | --- |
| `MouseEvent` with `mouse.ok`, a widget under the cursor whose `hits()` is true | That widget (`hit_test` of `mouse_point()`). |
| `MouseEvent` with no widget under the cursor, or `mouse.ok` false | The focused widget. |
| `KeyEvent`, `TickEvent`, `ResizeEvent` | The focused widget. |

From the first widget the event [bubbles up](/reference/event#dispatch-and-bubbling) to the root. Mouse events only arrive when `mouse` is `true`. Routing does not change the focus. To focus what was clicked, call `focus(id)` yourself.

```salam
mut ev := basalam.Event {}
until screen.next_event(ev):
    if ev.kind == basalam.MouseEvent and ev.mouse.ok and ev.mouse.pressed:
        p := ev.mouse_point()
        _ := screen.focus(screen.hit_test(p.x, p.y)) // click-to-focus
    end
    _ := screen.dispatch(ev)
    screen.present()
end
```

### Write your own loop

This is the shape most applications use, because the application decides what unhandled keys mean:

```salam
screen.present()
mut ev := basalam.Event {}
until screen.next_event(ev):
    if not screen.dispatch(ev) and ev.is_char("q"):
        screen.stop()
    end
    screen.present()
end
```

<Note>
  Salam's `each` loop only iterates vectors, maps, arrays, and slices, so it cannot consume a live channel. `until screen.next_event(ev):` is the equivalent: Salam's `until` loops *while* its condition is true.
</Note>

### Or let the screen run it

If every key is handled by widgets, `run_with_tick` is enough. Lambdas capture by value in Salam, so share state with the callback through a global.

```salam
mut frames := 0

func main:
    mut screen := basalam.NewTerminalScreen(MyRoot {})
    screen.tick_ms = 100
    screen.start()
    defer screen.close()
    screen.run_with_tick((): frames += 1 end)
end
```

| --- | --- | --- |
| `PollMs` | `20` | How often, at most, the input thread wakes when no key arrives. Bounds `stop()` latency and, on Windows, the size poll; on POSIX a resize arrives as `SIGWINCH` instead. |

## The channel wrapper

```salam
pub struct Channel<T>:
    pub ch: chan.Chan<T>
    pub static func Open(capacity: i64): Channel<T>
end
```

The specification calls for `events: chan Event`. Salam cannot spell `chan.Chan<Event>` inside the package that declares `Event`, but it does resolve the type through a generic parameter. `Channel<T>` exists only to name the channel; use `screen.events.ch` for the full `std/chan` API.

## Running headless

A screen that was never started has no input thread and never writes to the terminal, but everything else works. Post events, consume them, and inspect the buffer:

```salam
mut s := basalam.NewScreen(MyRoot {}, 20, 5)
defer s.close()
_ := s.post(basalam.Event { kind = basalam.KeyEvent, key = term.Decode("a") })
s.stop()
mut ev := basalam.Event {}
until s.next_event(ev):
    _ := s.dispatch(ev)
end
s.present()
println s.buffer.row_text(0)
```
