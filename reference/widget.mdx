A widget is anything with the six methods of the `Widget` interface. Salam interfaces are structural: there is no `implements` keyword, so a struct that has the methods is a widget. A list, a button, and a panel are all `Widget`s, and the screen stores them side by side as `dyn basalam.Widget`.

## Widget

```salam
pub interface Widget:
    func render(buf: Buffer, bounds: Rect)
    func handle_event(event: Event): bool
    func focusable(): bool
    func bounds(): Rect
    func set_bounds(bounds: Rect)
    func preferred_size(max_width: int): Rect
end
```

### render

```salam
func render(buf: Buffer, bounds: Rect)
```

Draws the widget into `buf`. `bounds` is the widget's own rect, the same value `bounds()` returns. When the screen renders, `buf` is already clipped to `bounds`, so anything drawn outside is dropped. `buf.focused` is `true` while the widget holds the focus; use it to draw a focus indicator. See [Buffer](/reference/buffer).

### handle_event

```salam
func handle_event(event: Event): bool
```

Reacts to an [event](/reference/event). Return `true` to consume it. Return `false` to let it bubble to the widget's parent.

### focusable

```salam
func focusable(): bool
```

Returns `true` when the widget can take keyboard focus. Only focusable widgets take part in focus navigation.

### bounds and set_bounds

```salam
func bounds(): Rect
func set_bounds(bounds: Rect)
```

`set_bounds` moves and resizes the widget; `bounds` returns the last rect set. Widgets never position themselves. A [container](/reference/layout) calls `set_bounds` on its children, and the screen gives the root its bounds through `fit_root`; call `set_bounds` yourself only for widgets you place by hand.

### preferred_size

```salam
func preferred_size(max_width: int): Rect
```

The size the widget wants at `max_width`, as a `Rect` at `(0, 0)`. `max_width <= 0` means unbounded. The [layout engine](/reference/layout) reads it to size a child on the cross axis: a widget that cannot measure returns a rect with negative width and height as a sentinel, and the engine fills the axis instead. The `BaseWidget` default does exactly that, so a container or placeholder fills the axis.

## Rules for implementations

<AccordionGroup>
  <Accordion title="Methods are infallible">
    No method returns an error. A widget given a region too small to draw in draws what fits, or nothing. The buffer clips every write, so drawing outside the region is harmless.
  </Accordion>
  <Accordion title="Handlers are synchronous">
    `handle_event` runs on the main thread, between frames, and must return promptly. Do long work in your application, driven by tick events, not inside a handler.
  </Accordion>
  <Accordion title="Widgets never write to the terminal">
    Draw into the `Buffer` you are given. The screen owns terminal output.
  </Accordion>
</AccordionGroup>

## BaseWidget

```salam
pub struct BaseWidget:
    pub rect: Rect = Rect {}
end
```

`BaseWidget` implements every `Widget` method with a default. Embed it with `pub use basalam.BaseWidget` and override only what your widget needs. Your own methods win over the embedded ones.

| Method | Default |
| --- | --- |
| `render` | Draws nothing. |
| `handle_event` | Returns `false`, so every event bubbles on. |
| `focusable` | Returns `false`. |
| `bounds` | Returns `rect`. |
| `set_bounds` | Stores the rect in `rect`. |
| `preferred_size` | Returns the negative sentinel, so the layout engine fills the axis. |

<ResponseField name="rect" type="Rect">Storage for `bounds` and `set_bounds`. An embedding widget can read it directly as `this.rect`.</ResponseField>

On its own, a `BaseWidget` is an invisible, unfocusable widget that ignores every event. That makes it a handy container or placeholder.

## Storing widgets

Convert a widget to `dyn basalam.Widget` once, and keep that value. Salam boxes the widget, and every copy of the `dyn` value shares the box. Calling `set_bounds` or `handle_event` through any copy changes the one widget.

```salam
w := Counter { label = "apples" } as dyn basalam.Widget
copy := w
copy.set_bounds(basalam.Rect { width = 12, height = 1 })
println w.bounds().width // 12: both copies share the widget
```

<Warning>
  Salam has no downcast from `dyn` back to the concrete type, and `dyn` values cannot be compared with `==`. Once a widget is stored as `dyn basalam.Widget`, you reach it only through the six interface methods.
</Warning>
