A widget is anything with the nine methods of the `Widget` interface. Salam interfaces are structural: there is no `implements` keyword, so a struct that has the methods is a widget. A list, a button, and a panel are all `Widget`s, and the screen stores them side by side as `dyn basalam.Widget`.

## Widget

```salam
pub interface Widget:
    func render(buf: Buffer, bounds: Rect)
    func handle_event(event: Event): bool
    func focusable(): bool
    func hits(): bool
    func visible(): bool
    func bounds(): Rect
    func set_bounds(bounds: Rect)
    func preferred_size(max_width: int): Rect
    func measure(axis: Axis, max_width: int): Measure
end
```

### render

```salam
func render(buf: Buffer, bounds: Rect)
```

Draws the widget into `buf`. `bounds` is the widget's own rect, the same value `bounds()` returns. When the screen renders, `buf` is already clipped to `bounds`, so anything drawn outside is dropped. `buf.focused` is `true` while the widget holds the focus; use it to draw a focus indicator. See [Buffer](/reference/buffer).

### handle_event

```salam
func handle_event(event: Event): bool
```

Reacts to an [event](/reference/event). Return `true` to consume it. Return `false` to let it bubble to the widget's parent.

### focusable

```salam
func focusable(): bool
```

Returns `true` when the widget can take keyboard focus. Only focusable widgets take part in focus navigation. A hidden ancestor still excludes a widget that returns `true`; see [`visible`](#visible).

### hits

```salam
func hits(): bool
```

Returns `true` when hit-testing may land on this widget. The default is `true`. Override it to return `false` when the widget may paint and still refuse hits. The screen then skips it and keeps scanning the widgets under it. Refusing hits does not remove the widget from paint order or from focus. Hiding does remove it from focus, paint order, and hit testing; see [`visible`](#visible).

### visible

```salam
func visible(): bool
```

Returns `true` when the widget is on screen. The default is `true`. Override it to return `false` while the widget is hidden: focus navigation, painting, and hit testing then skip the widget and every descendant of it. A widget answers only for itself, so every consumer asks every widget on the path to the root.

### bounds and set_bounds

```salam
func bounds(): Rect
func set_bounds(bounds: Rect)
```

`set_bounds` moves and resizes the widget; `bounds` returns the last rect set. Widgets never position themselves. A [container](/reference/layout) calls `set_bounds` on its children, and the screen gives the root its bounds through `fit_root`; call `set_bounds` yourself only for widgets you place by hand.

### preferred_size

```salam
func preferred_size(max_width: int): Rect
```

The size the widget wants at `max_width`, as a `Rect` at `(0, 0)`. `max_width <= 0` means unbounded. The [layout engine](/reference/layout) reads it when [`measure`](#measure) cannot measure: a main-axis `Pref` that cannot measure, and a cross-axis natural size. A widget that cannot measure returns a rect with negative width and height as a sentinel, and the engine fills the axis instead. The `BaseWidget` default does exactly that, so a container or placeholder fills the axis.

### measure

```salam
func measure(axis: Axis, max_width: int): Measure
```

The natural extent along `axis` at `max_width`. `ok` is false when this widget cannot measure, and the layout engine then reads `preferred_size`. `extent` is the length in cells when `ok` is true. The `BaseWidget` default cannot measure (`ok` false, `extent` `0`). [Row and Column](/reference/layout#measurement) override it. Grid and Stack do not. Must not call `set_bounds`.

## Rules for implementations

<AccordionGroup>
  <Accordion title="Methods are infallible">
    No method returns an error. A widget given a region too small to draw in draws what fits, or nothing. The buffer clips every write, so drawing outside the region is harmless.
  </Accordion>

  <Accordion title="Handlers are synchronous">
    `handle_event` runs on the main thread, between frames, and must return promptly. Do long work in your application, driven by tick events, not inside a handler.
  </Accordion>

  <Accordion title="Widgets never write to the terminal">
    Draw into the `Buffer` you are given. The screen owns terminal output.
  </Accordion>
</AccordionGroup>

## BaseWidget

```salam
pub struct BaseWidget:
    pub rect: Rect = Rect {}
end
```

`BaseWidget` implements every `Widget` method with a default. Embed it with `pub use basalam.BaseWidget` and override only what your widget needs. Your own methods win over the embedded ones.

| Method | Default |
| --- | --- |
| `render` | Draws nothing. |
| `handle_event` | Returns `false`, so every event bubbles on. |
| `focusable` | Returns `false`. |
| `hits` | Returns `true`. Override it to paint without accepting hits. |
| `visible` | Returns `true`. Override it to hide the widget and its subtree from focus navigation, painting, and hit testing. |
| `bounds` | Returns `rect`. |
| `set_bounds` | Stores the rect in `rect`. |
| `preferred_size` | Returns the negative sentinel, so the layout engine fills the axis. |
| `measure` | Cannot measure: `ok` is false and `extent` is `0`. Row and Column override it. |

<ResponseField name="rect" type="Rect">
  Storage for `bounds` and `set_bounds`. An embedding widget can read it directly as `this.rect`.
</ResponseField>

On its own, a `BaseWidget` paints nothing, is unfocusable, reports itself visible, ignores every event, and still accepts hits. That makes it a handy container or placeholder. A click on its rect lands on it unless you override `hits`.

## Storing widgets

Convert a widget to `dyn basalam.Widget` once, and keep that value. Salam boxes the widget, and every copy of the `dyn` value shares the box. Calling `set_bounds` or `handle_event` through any copy changes the one widget.

```salam
w := Counter { label = "apples" } as dyn basalam.Widget
copy := w
copy.set_bounds(basalam.Rect { width = 12, height = 1 })
println w.bounds().width // 12: both copies share the widget
```

<Warning>
  Salam has no downcast from `dyn` back to the concrete type, and `dyn` values cannot be compared with `==`. Once a widget is stored as `dyn basalam.Widget`, you reach it only through the nine interface methods.
</Warning>
