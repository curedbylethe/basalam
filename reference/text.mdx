`Text` draws a string into a [buffer](/reference/buffer). It is the first concrete widget: give it content, align it, wrap it to its box, and paint it in one style. Supply content once with `set_text`, or give the widget a source to read during render and measurement.

```salam
mut t := basalam.NewText("Hello, terminal")
t.set_align(basalam.Alignment.Center)
t.set_style(basalam.Style { fg = basalam.Green })
```

## Text

`Text` embeds [BaseWidget](/reference/widget), overrides the default `render`, and adds `preferred_size` and `preferred_width`; it inherits the rest of the `Widget` interface unchanged.

```salam
pub struct Text:
    pub use BaseWidget

    pub content: str = ""
    pub align: Alignment = Alignment.Left
    pub style: Style = StyleDefault
    pub wrap: WrapMode = WrapMode.Word
end
```

<ResponseField name="content" type="str">
  The last text passed to `set_text`. An explicit `"\n"` starts a new line. This value is ignored while a source is set.
</ResponseField>

<ResponseField name="align" type="Alignment">
  Horizontal placement of each line. Defaults to `Alignment.Left`.
</ResponseField>

<ResponseField name="style" type="Style">
  How the content is drawn. Defaults to `StyleDefault`, the terminal's default style.
</ResponseField>

<ResponseField name="wrap" type="WrapMode">
  How the content becomes lines at render time. Defaults to `WrapMode.Word`.
</ResponseField>

## Content

```salam
pub func NewText(content: str): Text
pub func set_text(content: str)
pub func set_source(src: func () str)
pub func clear_source()
```

`NewText` creates a widget with the content already set: left-aligned, unstyled, and word-wrapped. `set_text` replaces pushed content. `set_source` supplies a function that returns current content, and `clear_source` returns to the last pushed text. The last setter wins. A source is read at render and measure time, so keep its result stable within a frame.

Set the source before `Screen.add`, because `Screen.add` stores a copy of the widget. Closures capture by value; read module-level state or a shared holder inside the source. A changed value does not repaint or relayout automatically. Call `invalidate(id)`, register a tick, or call `set_bounds` again. A preferred-size change takes effect on the next bounds pass.

| Method | Description |
| --- | --- |
| `set_source` | Read current text from a function at render and measure time. |
| `clear_source` | Return to the last value passed to `set_text`. |

Use a module-level value or shared holder when source content must change. This example reads a module-level value:

```salam
include "basalam/basalam.salam"

mut live := "ready"

func main:
    mut t := basalam.NewText("")
    t.set_source((): ret live end)
    mut buf := basalam.NewBuffer(8, 1)
    defer buf.free()
    t.render(buf, basalam.Rect { width = 8, height = 1 })
    println buf.row_text(0)
end
```

## Alignment

```salam
pub enum Alignment:
    Left
    Center
    Right
end
```

| Value | Effect |
| --- | --- |
| `Left` | Lines start at the box's left edge. The default. |
| `Center` | Lines are centred. |
| `Right` | Lines end at the box's right edge. |

Alignment places each wrapped line on its own. For `Center`, a line's offset is `floor(free / 2)` cells, where `free` is the box width minus the line width, so when the slack is odd the extra cell lands on the **right**:

- Box width `11`, line `"abc"` (3 cells), free `8` → offset `4`.
- Box width `10`, line `"abc"` (3 cells), free `7` → offset `3`, one cell of slack on the right.

`set_align` changes the alignment.

## Wrapping

```salam
pub enum WrapMode:
    Word
    None
end
```

| Value | Effect |
| --- | --- |
| `Word` | Greedy word-boundary wrapping at the box width. The default. |
| `None` | Each explicit line is drawn as-is; the box edge clips it. |

Under `WrapMode.Word`:

- The widget walks the words of a paragraph. When the next word would cross the width, it starts a new line and the space at the break is consumed.
- A word longer than the width is cut at display-cell boundaries. A two-cell glyph may form a line wider than a one-cell box; the buffer blanks it when both cells cannot fit.
- An explicit `"\n"` starts a new paragraph, and each paragraph wraps on its own.

`set_wrap` changes the mode. A box width of `0` or less means unbounded, so every paragraph is returned unwrapped.

## Clipping

Drawing is a hard clip: a line keeps its first `W` cells and the box keeps its first `H` lines. There is no ellipsis, no scroll, and no overflow marker.

- Vertical: at most `height` lines are drawn.
- Horizontal: reachable under `WrapMode.None`, and for a two-cell glyph in a one-cell `Word` box. A `None` line longer than the box is cut at the right edge; a wide glyph that cannot fit both cells is blanked by the buffer.

A box with `width <= 0` or `height <= 0` draws nothing and never panics.

## Style

`style` is a [`Style`](/reference/style) value:

```salam
t.set_style(basalam.Style { fg = basalam.Cyan, bg = basalam.Black, bold = true })
```

A style is a plain value, so a partial literal leaves every other field at its default and `StyleDefault` is the style that asks for nothing.

`render` paints in two passes. It fills the whole box with the style's background only, so a background colour reads full-bleed across the widget's area while nothing else reaches the padding. It then writes each line of glyph cells — interior spaces included, so an underline stays continuous — in the full style. Both are `Style` values handed to the buffer, which builds the SGR bytes at `buf.tier` when it emits the frame. `Screen.start()` sets that tier to the terminal's detected capability; a buffer built by hand keeps `ColorTier.TrueColor`.

## Preferred size

```salam
pub func preferred_size(max_width: int): Rect
pub func preferred_width(): int
```

`preferred_size` returns the size the active content wants at `max_width`, as a `Rect` at `(0, 0)`: wrap at `max_width`, then width is the longest resulting line in display cells and height is the number of resulting lines. `max_width <= 0` means unbounded, so width is the longest explicit line and height is the explicit line count. A source that changes its preferred size is picked up on the next bounds pass.

`preferred_width` is the longest explicit line of the content, in cells — the unbounded width.

Neither includes a border or padding: the widget draws no frame of its own. To frame text, wrap it in a [`Panel`](/reference/panel).

<Note>
  Preferred size always measures with the wrap rules above, whatever `wrap` is set to.
</Note>

## Line functions

`WrapText` and `MeasureText` are the pure rules `Text` draws through. They hold no state and know nothing about widgets; the [layout engine](/reference/layout) sizes text through them, by way of `Text.preferred_size`.

```salam
pub func WrapText(text: str, width: int): Vector<str>
pub func MeasureText(text: str, max_width: int): Rect
```

`WrapText` splits `text` into display lines measured in cells, top to bottom, using the wrapping rules above. A two-cell glyph can exceed a width of one. `width <= 0` means unbounded, so each paragraph is returned unwrapped.

`MeasureText` returns the preferred size of `text` wrapped at `max_width`, as a `Rect` at `(0, 0)`. Widths count display cells.

## Example

A buffer is plain memory, so you can render and inspect a widget without a terminal:

```salam
include "basalam/basalam.salam"

func main:
    mut t := basalam.NewText("the quick brown fox")
    t.set_align(basalam.Alignment.Center)
    mut buf := basalam.NewBuffer(11, 2)
    defer buf.free()
    t.render(buf, basalam.Rect { width = 11, height = 2 })
    println "[" + buf.row_text(0) + "]" // [ the quick ]
    println t.preferred_size(11).width, t.preferred_size(11).height // 9 2
end
```

<Warning>
  A display cell is one terminal column. East Asian wide and fullwidth codepoints take two cells; controls, combining marks, and format codepoints take zero; other codepoints take one. The shared width table covers common wide and fullwidth blocks, not the full East Asian Width data. A rare wide codepoint outside those blocks still counts as one and can shift a column. `Text`, `Table`, `Buffer`, and the block widgets use this same rule. Zero-width codepoints are dropped when written to a buffer; grapheme clusters are not combined.
</Warning>
